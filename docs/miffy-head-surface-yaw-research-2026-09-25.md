# Miffy 左右轉頭：v23 退件後的曲面投影研究

狀態：研究及下一候選設計；**沒有製作 v24，也沒有啟用新的左右轉頭**。v22 的小幅平面側傾仍可使用；v23 的左右微轉經使用者動態檢視判定不像轉頭，僅留作退件證據。表情仍未製作。

## v23 錯在哪裡

`viewer/head-yaw-field.mjs` 的 v23 模型本質上只算 `x' = x + 位移(x,y)`，再讓位移於頸根附近漸減為零。它沒有每個像素或五官的深度 `z`，也沒有 3D 旋轉角 `θ`，因此只會讓頸部和頭部附近像橡皮片般橫向扭動。先前逐像素歸零、下界不動、沒有白邊等檢查只證明畫面沒有技術破綻，**不能證明它像頭部轉向**。本候選不可用「再加強位移」補救。

## 使用者的球面想法：方向正確，但球不是完整答案

若表面上一點已有 3D 位置 `(x,y,z)`，繞垂直軸轉 `θ` 時，先計算 `xθ = x cosθ + z sinθ`、`zθ = z cosθ − x sinθ`，再投影到畫面。不同 `z` 的眼角、鼻、嘴與臉側輪廓會產生不同位移和可見寬度；遠側會因透視與遮擋變窄。這是以 3D 旋轉矩陣和相機投影得出的**示意模型**，不是 Live2D 的唯一公式。[OpenCV 3D 點投影文件](https://docs.opencv.org/4.11.0/javadoc/org/opencv/calib3d/Calib3d.html)

橢球可作為臉頰／額頭的粗深度先驗，但鼻尖較突出、眼球／眼皮並非貼在同一球面，嘴唇也有自身厚度，耳朵在臉後側；一個完美球面無法忠實表現角色。更重要的是，**正面圖不能唯一決定深度與被遮住的顏色**。公式能投影已知的 3D 表面，不能從一張正面 PNG 還原 Miffy 真正的側面。

## 專業流程如何處理

- Live2D 官方 XY 教學不是把整臉水平拉動，而是為臉輪廓、左右眼、鼻、嘴、眉、耳與各束髮建立各自的變形器，調整遠側較窄、近側較寬的形狀，並檢查參數連續運動及斜角。[Live2D XY 臉部教學](https://docs.live2d.com/en/cubism-editor-tutorials/xy/)
- 其半自動臉部動態同樣先要求臉、左右眼／眼球、左右眉、左右耳、嘴和鼻等可分別定位的素材；這表示數學或自動工具仍要有正確的零件結構。[Live2D 臉部動態自動生成](https://docs.live2d.com/en/cubism-editor-manual/face-auto-edit/)
- Live2D 的 3D 旋轉輔助能用深度來生成近似關鍵形，但深度估計需要非正面的關鍵形；預設正面形不能單獨提供這項資訊。[Live2D 3D 旋轉表現](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression/)
- 官方素材分離教學要求會因動作露出的部分先補線與顏色。轉頭時的髮際、臉側、耳後與頸交界不能靠投影公式憑空補出。[Live2D 素材分離](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)

## Miffy 下一步：先驗證幾何，不再直接扭圖

1. 回到 v22 作外觀基線，鎖住 v23 為退件證據。從 `Miffy_face_bd.png` 與 `emotion_type01～04` 標示臉輪廓、雙眼內外眼角、鼻、嘴角、耳根、髮際、下巴和頸接點；表情圖只當視角／比例參考，先不要當中性臉零件直接拼貼。
2. 先做**只有線框與標記的幾何候選**：以橢球／局部深度作初始推測，讓同一轉角分別投影眼、鼻、嘴、輪廓；在畫面顯示近遠側縮放、遮擋與旋轉中心。與表情圖的實際眼距、嘴角、輪廓比例比對後，修正深度；這一步不修改角色 PNG。
3. 幾何方向確認後，再盤點正面整頭中仍烘焙的眉、鼻、嘴、耳和臉線。要真正分別調整透視，必須建立**來源忠實的無五官底圖與獨立零件**，同時補上會露出的皮膚／髮際。使用現有來源能移植的像素；原畫沒有的區域交由使用者補畫或先審核生成參考，不能自行假裝有原畫。
4. 最後才做新左右角度候選，從小範圍開始並測正負端點、中間幀、眨眼／視線、v22 側傾、頭髮獨立擺動與返回正面。須同時達到歸零像素一致和「肉眼看得出弧面轉向」；單靠機器差異值不算通過。

目前不提出「安全可用角度」的數字，也不修改正式品質基準、公開 v21 或既有原畫。完成使用者認可的幾何／零件候選後，再將經驗回寫 `character-motion-rig` SKILL。

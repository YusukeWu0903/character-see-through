# Miffy 頭部三軸有限旋轉：資料研究與實作門檻

狀態：**研究結論，尚未製作候選，也未改動 v21**。Miffy 目前沒有表情功能；先前的微笑已撤除。本研究只處理頭部姿態，不能把它稱作已完成表情。

## 軸的名稱先對齊

在數學／3D 座標中，pitch 通常繞 X 軸、yaw 繞 Y 軸、roll 繞 Z 軸。但 Live2D 的參數名稱是以**可見動作**命名：`ParamAngleX` 是臉朝左右、`ParamAngleY` 是抬低頭、`ParamAngleZ` 是平面側傾。介面宜寫「左右轉／抬低頭／側傾」，資料結構另記明所用座標慣例，避免把 X/Y 的數學軸和 Live2D 名稱混淆。Live2D 文件列出的 ±30 是通用參數範例，**不是** Miffy 可安全達到的角度。[Live2D 標準參數表](https://docs.live2d.com/en/cubism-editor-manual/standard-parameter-list/)

## 正式資料的共同結論

- Live2D 的 Z 側傾使用頭部旋轉變形器；X/Y 左右與上下朝向使用透視感的 warp deformer。官方 XY 教學明確建議把臉輪廓、左右眼、鼻、嘴、眉、耳與前後／左右髮分開變形，不把整張臉塞入唯一變形器；X/Y 的斜角還要檢查四角組合。[Z 側傾教學](https://docs.live2d.com/en/cubism-editor-tutorials/deformer/)、[XY 臉部教學](https://docs.live2d.com/en/cubism-editor-tutorials/xy/)
- Live2D 的半自動臉部動態先要求臉、左右眼／眼球／眉、耳、嘴、鼻等 ArtMesh 分屬獨立部位，並只適用正面臉。這支持「先整理素材與父子層級，再產生動態」，不支持從一張合成臉直接取得可靠的三軸轉頭。[Live2D 臉部動態自動生成](https://docs.live2d.com/en/cubism-editor-manual/face-auto-edit/)
- Live2D 的「3D 旋轉表現」是估計 3D 形狀並產生 2D 變形關鍵形；要估深度須選**非正面**的關鍵形，正面默認形本身不提供側面的深度資訊。因此它可輔助 2.5D 姿態，不能證明單張正面原圖能忠實還原真實側面。[Live2D 3D 旋轉表現](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression/)
- 官方拆圖說明要求會移動、或移開後會露出的部分預先補足線與顏色。這對耳根、臉頰外側、髮際和下巴／頸接合尤其重要。[Live2D 素材分離](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)
- Spine 的 mesh/deform 可作為局部形變和骨架父子關係的參考，但其 2D mesh 本身不會從正面圖自動生成可信的臉部側面。[Spine mesh 官方指南](https://us.esotericsoftware.com/spine-meshes)

## 對 Miffy v21 的診斷

`_review/motion_v21/rig.json` 沿用 v6 的頭部父節點：頭的 `maxDegrees` 為 0，現有控制主要服務雙腳接地時的頭部穩定，不是 yaw/pitch/roll。`viewer/assembly-motion.mjs` 在繪製 `face` 時額外合成眼睛／眨眼素材，前後髮是頭的子節點但可獨立微動。高解析光頭參考 `Character/002_Miffy/Miffy_face_bd.png` 仍把眉、鼻、嘴、耳與部分眼部外觀畫在整頭上；目前的眼部候選只為眨眼與視線提供局部動態覆蓋，**不是**完整可分別透視的五官樹。也沒有側面或 3/4 頭像可用作真實新露出區域。

由此推論：**有限 2.5D 三軸姿態可做候選；真實三維旋轉或較大的 X/Y 轉角，現有單張正面素材不足。** 整顆頭剛性轉 Z 比較直接；對 X/Y 只把光頭 PNG 壓縮、平移或套一張共用網格，會讓鼻、雙眼、嘴和耳一起像紙片滑動，且可能讓已修好的耳根、髮際與頸接縫復發。

## 建議的候選順序（未授權正式啟用）

1. **素材和遮擋盤點**：保留 v21 原檔，量測臉輪廓、左右耳／眼／眉、鼻、嘴、下巴、髮際及頸樞軸；標出 baked 特徵、前後髮遮擋和轉向後會露出的缺圖。需獨立變形的特徵先建立來源忠實、無重影的底圖與零件。沒有原畫依據的隱藏耳／側面不得擅畫。
2. **Z 軸候選**：讓光頭與其五官同一頭部父節點，以頸根為樞軸作有限側傾；前後髮繼承頭部姿態、保留原本次級擺動。先證明歸零像素與 v21 完全一致，並檢查耳根、髮際、下巴／頸、肩帶。
3. **X/Y 軸候選**：臉輪廓與左右五官採各自的來源對位網格／關鍵形，共用 `headX/headY` 驅動；眼睛的閉合、眼白遮罩及視線在**頭部局部座標**內完成，再跟著頭部變形。先以極小幅度測試，逐級增加到第一個明顯穿幫前，不照搬 Live2D 的通用角度。若需要明顯 3/4 效果，須有使用者核准的左右／上下參考圖或人工補繪遮蔽區。
4. **交互驗收**：顯示由真實網格、錨點與遮擋遮罩生成的預設關閉檢視圖。分別檢查 X、Y、Z 正負極值、X/Y 四角、眨眼開／半／閉、九方向視線、頭髮獨立擺動及身體待機／滑鼠跟隨；確認中間幀、返回歸零與效能。任何中途出現雙眼分岔、嘴／鼻重影、假耳、髮際裂縫或頸接縫，先縮回或修素材，不進正式版。

此研究不建立表情，也不更動 Miffy 的公開 v21、候選資產、品質基準或 SKILL。經第一個可視候選驗證後，再把真正可重用的頭部動態準則補入 `character-motion-rig`，避免把尚未驗證的數值寫成通則。
